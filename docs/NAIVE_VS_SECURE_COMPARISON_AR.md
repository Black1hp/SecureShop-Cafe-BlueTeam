# خطة مقارنة النسخة الضعيفة بالنسخة المحمية

المطلوب إثبات عملي لكل موضوع في بيئة تعليمية معزولة يملكها الفريق. **هذه خطة وليست ادعاء بأن المقارنات اكتملت.**

| موضوع | نموذج ضعيف معزول | نسختنا المحمية | الدليل المطلوب |
|---|---|---|---|
| Price Tampering | نموذج تعليمي يقبل السعر القادم من الطلب | Checkout يستخرج السعر من SQLite | إجمالي الطلب قبل/بعد |
| Coupon Reuse | غياب قيد الاستخدام الواحد | `coupon_uses` وفحص داخل Transaction | محاولتان بنفس الكود |
| MFA account binding | اختيار حساب الـOTP من نموذج العميل | `pending_user_id` في session | رفض OTP مستخدم آخر |
| CSRF | نموذج POST بلا CSRF Token | رفض Mutation بلا Token | HTTP status |
| IDOR | استعلام طلب برقم ID فقط | قيد `user_id` للطلب | رفض طلب المستخدم الثاني |
| AuthZ | صفحة Admin بلا فحص الدور | فحص `role=admin` في السيرفر | رفض 403 |
| XSS/SQLi | عرض مدخلات بلا escape / concatenated query | escaping / placeholders | نسخة اختبارية بمدخلات غير آمنة ورفضها |
| Typing Risk | لا يوجد baseline | خمس عينات ورصد `behavior_anomaly` | event من Audit (مع تاريخ) |
| WebAuthn | تجاهل RP/Origin/Challenge/Signature | فحص ES256 والتحدي/الأصل | اختبارات توقيع صحيح/خاطئ |
| Location/Time | لا توجد سياسة | Haversine + Cairo server hour | سيناريوهات وحدود السماح والرفض |

**تنبيه:** لا تستهدفي موقعًا عامًا أو نظامًا لا يخصكم. لا ترفقي مفاتيح أو رموزًا حقيقية. لا تُدرجي أي لقطة للشاشة باعتبارها دليلًا إن لم تُلتقط فعلًا.
